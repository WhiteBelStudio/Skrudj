# Подключение сообщества VK к «Скрудж Макдак»

## 1. Подготовить сообщество

1. Откройте управление своим сообществом VK.
2. В разделе работы с API создайте ключ доступа сообщества с минимально необходимыми правами для планируемых функций. Не публикуйте ключ.
3. Включите Callback API и создайте сервер.
4. Скопируйте числовой ID сообщества, секретный ключ Callback API и строку подтверждения.
5. На первом этапе выберите событие подтверждения сервера. События сообщений подключайте после завершения обработчика сообщений.
6. Проверьте, что значения скопированы без лишних пробелов и что ключ доступа сообщества и секрет Callback API взяты из разных полей.

Названия разделов VK могут отличаться в зависимости от типа сообщества и интерфейса.

## 2. Настроить переменные окружения

Заполните переменные на сервере или в локальном файле `.env`. Не вставляйте реальные секреты в GitHub, сообщения или логи.

- `VK_GROUP_TOKEN` — ключ доступа сообщества для будущих вызовов VK API, включая отправку сообщений. Хранится как секрет.
- `VK_GROUP_ID` — положительный числовой ID сообщества без знака `-`.
- `VK_CALLBACK_SECRET` — секретный ключ из настроек Callback API. Это отдельное значение, не заменяйте его ключом доступа сообщества.
- `VK_CONFIRMATION_CODE` — строка подтверждения сервера из настроек Callback API.
- `VK_CALLBACK_HOST` — адрес привязки сервера; обычно `0.0.0.0` в контейнере.
- `VK_CALLBACK_PORT` — порт сервера; по умолчанию `8080`.

Пустые значения токена, секрета и кода подтверждения трактуются как незаданные. Некорректный ID сообщества (ноль, отрицательное или нечисловое значение) отклоняется конфигурацией.

Сервер Callback запускается, когда заполнены ID сообщества, секрет Callback API и код подтверждения. Для исходящих запросов к VK API дополнительно понадобится ключ доступа сообщества. На этом этапе приложение проверяет формат конфигурации, но не выполняет автоматическую проверку токена через VK API: действительность токена можно подтвердить только реальным запросом с корректными правами.

## 3. Настройка Pterodactyl

1. Подготовьте сервер с Python 3.12 и загрузите актуальное содержимое репозитория.
2. В Startup Command укажите `python start.py`. Скрипт устанавливает проект в editable-режиме, если пакет ещё не установлен, затем запускает приложение.
3. В разделе Network создайте/назначьте порт (allocation). Укажите этот же номер в `VK_CALLBACK_PORT`; оставьте `VK_CALLBACK_HOST=0.0.0.0`.
4. Добавьте переменные окружения из списка выше в настройках сервера, если egg позволяет это делать. Если нет — создайте файл `.env` в корне проекта. Не коммитьте его.
5. Запустите сервер и проверьте консоль: ожидается сообщение `VK Callback API listening on 0.0.0.0:НОМЕР_ПОРТА`, если обязательные настройки заполнены.
6. Если в консоли нет этого сообщения, проверьте `VK_GROUP_ID`, `VK_CALLBACK_SECRET`, `VK_CONFIRMATION_CODE`, порт и сообщения об ошибках запуска.

Важно: наличие allocation само по себе не гарантирует публичный HTTPS. Если Pterodactyl не предоставляет HTTPS-домен для выделенного порта, понадобится внешний HTTPS reverse proxy или домен/туннель, разрешённый правилами твоего хостинга. Не используй случайный публичный прокси для передачи запросов с секретом Callback API.

## 4. Адрес Callback API

Публичный URL должен быть доступен по HTTPS. Укажите в настройках VK адрес:

`https://ВАШ-ДОМЕН/vk/callback`

Приложение слушает внутренний порт `8080`; HTTPS обычно завершается на прокси/входном маршрутизаторе хостинга. Не указывайте примерный домен буквально. Если хостинг не предоставляет HTTPS и публичный маршрут, настройте домен и HTTPS до подключения VK.

Для проверки работоспособности предусмотрен маршрут:

`GET /health/live`

Он возвращает только статус сервиса и не раскрывает конфигурацию.

## 5. Подтверждение и безопасность

- VK должен прислать событие `confirmation`; сервер возвращает заданную строку подтверждения обычным текстом.
- Для Callback-запросов проверяются ID сообщества и отдельный секрет Callback API.
- Неверный ID или секрет отклоняются.
- Не публикуйте логи с токенами и секретами.
- Не открывайте внутренний порт напрямую без необходимости; предпочтителен HTTPS-прокси.

## 6. Критерии завершения пункта 1

- [ ] Создан ключ доступа сообщества с минимальными нужными правами.
- [ ] Получен и указан правильный положительный ID сообщества.
- [ ] Получен отдельный секрет Callback API.
- [ ] Получен код подтверждения сервера.
- [ ] Все четыре значения сохранены в переменных окружения, а не в Git.
- [ ] Параметры конфигурации проходят тесты.
- [ ] После настройки будет выполнена реальная проверка подтверждения сервера и действительности токена.

Успешное подтверждение доказывает, что VK может достучаться до Callback endpoint. Оно **не** означает, что готов пользовательский бот: обработка входящих сообщений, кнопок, фотографий, объявлений и модерации реализуется следующими задачами этапа 2.

Реальное подключение нельзя подтвердить без доступа к настройкам сообщества и публичному адресу развёрнутого сервера.
